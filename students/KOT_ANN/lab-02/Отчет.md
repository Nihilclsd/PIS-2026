### Часть 1. Архитектурная диаграмма

**Response Processor Service**  _управляет асинхронной обработкой ответов респондентов в системе «Откликнись»: обогащение ответов гео-данными, классификация на «качественные» и «отписки» (антиспам), сохранение с агрегацией статистики, триггерные уведомления авторов форм при критических оценках._

**Основные операции:**
- Приём сырого ответа из очереди сообщений
- Валидация ответа по схеме формы
- Обогащение гео-данными (страна/город по IP)
- Определение типа устройства (мобильный/десктоп, ОС, браузер)
- Расчёт времени заполнения формы
- Анализ на отписки через антиспам-движок
- Сохранение обогащённого ответа в БД
- Обновление агрегированных метрик формы (total_responses, quality_responses, average_rating)
- Отправка уведомлений автору формы при низких оценках (триггеры)

**Ключевые сущности:**
- **Response (Ответ)** — доменная сущность, содержащая данные ответа респондента, метаданные (IP, User-Agent), обогащённые данные (гео, устройство, время заполнения) и результат классификации (quality_score, is_suspect)
- **Form (Форма)** — доменная сущность, хранящая схему полей и настройки антиспама (минимальное время заполнения, минимальная длина комментария, блокировка повторяющихся символов)
- **FormAggregates (Агрегаты формы)** — Value Object с накопительной статистикой по форме (всего ответов, качественных, подозрительных, средний рейтинг)

```python
# domain/models/response.py

from typing import Dict, Any, Optional
from datetime import datetime


class Response:
    """Доменная модель ответа на форму"""
    
    def __init__(
        self,
        response_id: str,
        form_id: str,
        answers: Dict[str, Any],
        started_at: datetime,
        submitted_at: datetime,
        ip_address: Optional[str] = None,
        user_agent: Optional[str] = None
    ):
        self.id = response_id
        self.form_id = form_id
        self.answers = answers
        self.started_at = started_at
        self.submitted_at = submitted_at
        self.ip_address = ip_address
        self.user_agent = user_agent
        
        # Обогащённые данные (заполняются позже)
        self.geo_country: Optional[str] = None
        self.geo_city: Optional[str] = None
        self.device_type: Optional[str] = None
        self.filling_time_sec: Optional[int] = None
        self.quality_score: Optional[float] = None
        self.is_suspect: Optional[bool] = None
        self.suspect_reason: Optional[str] = None
    
    def calculate_filling_time(self) -> int:
        """Вычисляет время заполнения формы в секундах"""
        delta = self.submitted_at - self.started_at
        return int(delta.total_seconds())
    
    def enrich_geo(self, country: str, city: str) -> None:
        """Обогащает ответ гео-данными"""
        self.geo_country = country
        self.geo_city = city
    
    def enrich_device(self, device_type: str) -> None:
        """Обогащает ответ данными об устройстве"""
        self.device_type = device_type
    
    def classify(
        self, 
        quality_score: float, 
        is_suspect: bool, 
        suspect_reason: Optional[str] = None
    ) -> None:
        """Классифицирует ответ (качественный / отписка)"""
        self.quality_score = quality_score
        self.is_suspect = is_suspect
        self.suspect_reason = suspect_reason
    
    def is_quality_response(self) -> bool:
        """Проверяет, является ли ответ качественным"""
        return self.is_suspect is False
```

from typing import List, Dict, Any, Optional


class FormField:
    """Value Object: Поле формы"""
    
    def __init__(
        self,
        name: str,
        field_type: str,
        required: bool = False,
        constraints: Optional[Dict[str, Any]] = None
    ):
        self.name = name
        self.field_type = field_type
        self.required = required
        self.constraints = constraints or {}


class AntiSpamSettings:
    """Value Object: Настройки детекции отписок"""
    
    def __init__(
        self,
        min_filling_time_sec: int = 30,
        min_comment_length: int = 3,
        block_repeating_chars: bool = True
    ):
        self.min_filling_time_sec = min_filling_time_sec
        self.min_comment_length = min_comment_length
        self.block_repeating_chars = block_repeating_chars


class Form:
    """Доменная модель формы"""
    
    def __init__(
        self,
        form_id: str,
        fields: List[FormField],
        anti_spam_settings: Optional[AntiSpamSettings] = None
    ):
        self.id = form_id
        self.fields = {f.name: f for f in fields}
        self.anti_spam_settings = anti_spam_settings or AntiSpamSettings()
    
    def get_field(self, name: str) -> Optional[FormField]:
        """Возвращает поле по имени"""
        return self.fields.get(name)
    
    def is_field_required(self, field_name: str) -> bool:
        """Проверяет, является ли поле обязательным"""
        field = self.get_field(field_name)
        return field.required if field else False

#### Бизнес-правила

1. Время заполнения формы вычисляется как разница между `submitted_at` и `started_at`
2. Ответ можно обогатить гео-данными (страна, город) через `enrich_geo()`
3. Ответ можно обогатить данными об устройстве через `enrich_device()`
4. Ответ можно классифицировать как «качественный» или «отписка» через `classify()`
5. Качественный ответ определяется по флагу `is_suspect = False`
6. Форма хранит поля в виде словаря для быстрого доступа по имени
7. У каждой формы есть настройки антиспама со значениями по умолчанию (30 сек, 3 символа)
8. Агрегаты формы обновляются через методы `increment_total()`, `increment_quality()`, `increment_suspect()`
9. Все доменные ошибки наследуются от базового `DomainException`
10. Форма может содержать вложенный Value Object `FormField` с типом и обязательностью

### Часть 4. Application Layer (Прикладной слой)

#### Входящие порты (Inbound Ports)

**ProcessResponseUseCase** — интерфейс для обработки ответа. Содержит метод `process(command: ProcessResponseCommand) -> None`. ProcessResponseCommand — DTO с полями: response_id, form_id, answers, ip_address, user_agent, started_at, submitted_at.

**GetAggregatesUseCase** — интерфейс для получения статистики формы. Содержит метод `get_aggregates(form_id: str)`.

#### Исходящие порты (Outbound Ports)

**FormSchemaRepository** — интерфейс для доступа к схемам форм. Содержит метод `find_by_id(form_id: str)`.

**ResponseRepository** — интерфейс для хранения ответов. Содержит методы: `save(response)`, `exists(response_id) -> bool`, `update_aggregates(form_id, response)`.

**GeoService** — интерфейс для геолокации. Содержит метод `get_location(ip_address) -> Tuple[str, str]`.

**AntiSpamService** — интерфейс для детекции отписок. Содержит метод `analyze(answers, filling_time_sec, form_settings) -> AntiSpamResult`. AntiSpamResult содержит quality_score, is_suspect, suspect_reason.

**NotificationService** — интерфейс для уведомлений. Содержит метод `notify_critical_feedback(form_id, response_id, rating, comment)`.

#### Application Service

**ResponseProcessor** — реализует входящие порты ProcessResponseUseCase и GetAggregatesUseCase.

Конструктор принимает пять зависимостей: form_repository, response_repository, geo_service, anti_spam_service, notification_service (инжекция через конструктор, принцип Dependency Inversion).

Метод `process()` содержит TODO (будет реализован в Lab #4). Планируемая логика: получение схемы формы → создание Response → валидация → обогащение гео → парсинг User-Agent → расчёт времени → антиспам → сохранение → обновление агрегатов → уведомления при триггере.

Метод `get_aggregates()` содержит TODO (будет реализован в Lab #4).

#### Принципы Application Layer

- Dependency Inversion: сервис зависит от абстракций (портов), а не от конкретных реализаций
- Единственная ответственность: каждый порт отвечает за одну операцию
- Изоляция домена: Application слой не содержит бизнес-логики, только координацию
- DTO для передачи данных: ProcessResponseCommand группирует параметры

### Часть 5. Infrastructure Layer (Инфраструктурный слой)

#### Входящий адаптер: Queue Consumer

**QueueConsumer** — забирает сообщения из очереди (RabbitMQ/Kafka) и вызывает входящий порт ProcessResponseUseCase.

Конструктор принимает processor: ProcessResponseUseCase.

Метод `on_message(raw_message: str)` — парсит JSON, создаёт ProcessResponseCommand и вызывает processor.process(command).


#### Исходящий адаптер: InMemoryFormRepository

**InMemoryFormRepository** — реализует порт FormSchemaRepository.

Хранит формы в словаре `_forms: Dict[str, Form]`.

Метод `find_by_id(form_id)` возвращает форму из словаря или None.

Метод `_init_sample_data()` заполняет тестовыми данными: форма FORM-42 с полями name (text, required), rating (integer, required), comment (text, optional) и настройками антиспама (min_filling_time_sec=30, min_comment_length=3, block_repeating_chars=True).

#### Исходящий адаптер: InMemoryResponseRepository

**InMemoryResponseRepository** — реализует порт ResponseRepository.

Хранит ответы в словаре `_responses: Dict[str, Response]`.

Хранит агрегаты в словаре `_aggregates: Dict[str, FormAggregates]`.

Метод `save(response)` — сохраняет ответ в словарь.

Метод `exists(response_id)` — проверяет наличие ключа в словаре.

Метод `update_aggregates(form_id, response)` — обновляет или создаёт FormAggregates для формы: increment_total(), increment_quality() или increment_suspect() в зависимости от флага is_suspect.

Метод `get_aggregates(form_id)` — возвращает агрегаты из словаря или None.

#### Исходящий адаптер: MockGeoService

**MockGeoService** — реализует порт GeoService.

Хранит тестовые данные в словаре `_MOCK_DATA`: IP 77.88.55.66 → (Россия, Москва), 8.8.8.8 → (США, Маунтин-Вью), 127.0.0.1 → (None, None).

Метод `get_location(ip_address)` — возвращает страну и город из словаря или (None, None).

Содержит TODO (в Lab #5 заменить на реальный HTTP-клиент к GeoIP API).

#### Исходящий адаптер: MockAntiSpamService

**MockAntiSpamService** — реализует порт AntiSpamService.

Метод `analyze(answers, filling_time_sec, form_settings)` — применяет простые правила:

- Если filling_time_sec < form_settings.min_filling_time_sec → quality_score=0.1, is_suspect=True, suspect_reason="filling_time_too_short"
- Если длина комментария < form_settings.min_comment_length → quality_score=0.3, is_suspect=True, suspect_reason="text_too_short"
- Если включена блокировка повторяющихся символов и текст состоит из повторяющихся символов → quality_score=0.15, is_suspect=True, suspect_reason="repeating_chars_only"
- Иначе → quality_score=0.95, is_suspect=False, suspect_reason=None

#### Исходящий адаптер: MockNotificationService

**MockNotificationService** — реализует порт NotificationService.

Метод `notify_critical_feedback(form_id, response_id, rating, comment)` — логирует сообщение с уровнем INFO: "[MOCK] Critical feedback notification: form={form_id}, response={response_id}, rating={rating}, comment='{comment}'".


#### Dependency Injection

**DependencyContainer** — конфигурация DI, связывает порты с адаптерами.

В конструкторе создаются исходящие адаптеры: InMemoryFormRepository, InMemoryResponseRepository, MockGeoService, MockAntiSpamService, MockNotificationService.

Затем создаётся ResponseProcessor с инжекцией всех пяти зависимостей.

Методы: `get_process_response_use_case()` возвращает ResponseProcessor, `get_get_aggregates_use_case()` возвращает ResponseProcessor, `get_queue_consumer()` возвращает QueueConsumer с ResponseProcessor.

#### Принципы Infrastructure Layer

- Зависимости направлены внутрь: Infrastructure зависит от Application (портов) и Domain
- Адаптеры реализуют порты, но не наоборот
- DI контейнер собирает все зависимости в одном месте
- Mock-адаптеры позволяют тестировать без реальных внешних сервисов

### Часть 6. Dependency Injection (Конфигурация зависимостей)

**DependencyContainer** — DI-контейнер, связывает порты с адаптерами.

В конструкторе создаются исходящие адаптеры: InMemoryFormRepository, InMemoryResponseRepository, MockGeoService, MockAntiSpamService, MockNotificationService.

Затем создаётся ResponseProcessor с инжекцией всех пяти зависимостей через конструктор.

Методы:
- `get_process_response_use_case()` — возвращает ResponseProcessor (как реализацию ProcessResponseUseCase)
- `get_get_aggregates_use_case()` — возвращает ResponseProcessor (как реализацию GetAggregatesUseCase)
- `get_queue_consumer()` — возвращает QueueConsumer с инжектированным ResponseProcessor

**Как работает DI**:

Все зависимости передаются через конструктор (constructor injection), а не создаются внутри класса. Это позволяет легко заменять реализации (например, InMemoryFormRepository на PostgreSQLFormRepository) без изменения кода ResponseProcessor. DependencyContainer собирает все компоненты в одном месте — при создании контейнера.

## 6. Выводы

### Что получилось хорошо

Удалось чётко отделить доменную логику от инфраструктуры. Domain слой не имеет зависимостей от фреймворков и внешних сервисов. Response, Form, FormAggregates содержат только бизнес-логику.

Порты и адаптеры разделены: входящие порты (ProcessResponseUseCase, GetAggregatesUseCase) определяют, что умеет сервис, исходящие порты (FormSchemaRepository, ResponseRepository, GeoService, AntiSpamService, NotificationService) определяют, что нужно сервису от внешнего мира.

DependencyContainer собирает все зависимости в одном месте, ResponseProcessor получает их через конструктор (constructor injection).

### С какими трудностями столкнулись

Было сложно понять, зачем создавать интерфейс для порта, если у него только одна реализация. После изучения принципа Dependency Inversion стало ясно: это для тестируемости и возможности замены адаптера (например, InMemoryFormRepository на PostgreSQLFormRepository) без изменения кода ResponseProcessor.

Также потребовалось время на разграничение ответственности между слоями: что идёт в Domain, что в Application, а что в Infrastructure.

### Что узнали нового

Изучена гексагональная архитектура (Ports & Adapters): бизнес-логика изолирована в центре, внешний мир подключается через порты и адаптеры.

Освоен принцип Dependency Inversion: зависимости направлены внутрь, к домену. Domain не знает о Application и Infrastructure.

Понято, как CQRS применяется на уровне портов: команды (ProcessResponseUseCase) и запросы (GetAggregatesUseCase) разделены.

### Как можно улучшить

Добавить реальную БД (PostgreSQL) вместо InMemory-репозиториев. Реализовать полноценный антиспам-движок вместо Mock-версии. Подключить реальный GeoIP сервис. Написать юнит-тесты для ResponseProcessor с моками. Добавить интеграционные тесты с TestContainers. Реализовать обработку Dead Letter Queue для сообщений, которые не удалось обработать после нескольких попыток.
