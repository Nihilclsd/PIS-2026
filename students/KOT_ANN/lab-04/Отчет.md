## Ход выполнения работы

### 1. Команды (Commands)

**Созданные команды:**

1. **ProcessResponseCommand** - команда для обработки ответа
   - Назначение: инициирует полный цикл обработки ответа (валидация, обогащение, классификация, сохранение)
   - Поля: response_id, form_id, answers, ip_address, user_agent, started_at, submitted_at
   - Валидация: response_id и form_id не пустые, answers не пустые, started_at не может быть после submitted_at
   - Файл: `application/command/process_response_command.py`

2. **ReclassifyResponseCommand** - команда для ручной переклассификации ответа
   - Назначение: позволяет вручную изменить классификацию ответа (качественный/отписка)
   - Поля: response_id, quality_score, is_suspect, suspect_reason
   - Валидация: response_id не пустой, quality_score в диапазоне 0-1, для отписки обязательно указание причины
   - Файл: `application/command/reclassify_response_command.py`

**Пример кода команды:**

```python
@dataclass(frozen=True)
class ProcessResponseCommand:
    response_id: str
    form_id: str
    answers: Dict[str, Any]
    ip_address: Optional[str]
    user_agent: Optional[str]
    started_at: datetime
    submitted_at: datetime
    
    def __post_init__(self):
        if not self.response_id or not self.response_id.strip():
            raise ValueError("response_id cannot be empty")
        if not self.form_id or not self.form_id.strip():
            raise ValueError("form_id cannot be empty")
        if not self.answers:
            raise ValueError("answers cannot be empty")
        if self.started_at > self.submitted_at:
            raise ValueError("started_at cannot be after submitted_at")
```

### 2. Command Handlers

**Созданные обработчики:**

1. **ProcessResponseHandler** - обработчик команды ProcessResponseCommand
   - Шаги обработки: получение схемы формы → создание Response → валидация → расчёт времени → обогащение гео → парсинг User-Agent → антиспам-анализ → классификация → сохранение → обновление агрегатов → уведомления при низкой оценке
   - Зависимости: FormSchemaRepository, ResponseRepository, GeoService, AntiSpamService, NotificationService
   - Файл: `application/command/handler/process_response_handler.py`

2. **ReclassifyResponseHandler** - обработчик команды ReclassifyResponseCommand
   - Шаги обработки: загрузка ответа → переклассификация → сохранение → обновление агрегатов (при изменении статуса)
   - Зависимости: ResponseRepository
   - Файл: `application/command/handler/reclassify_response_handler.py`

**Пример кода обработчика:**

```python
class ProcessResponseHandler:
    def __init__(self, form_repository, response_repository, geo_service, anti_spam_service, notification_service):
        self.form_repository = form_repository
        self.response_repository = response_repository
        self.geo_service = geo_service
        self.anti_spam_service = anti_spam_service
        self.notification_service = notification_service
    
    def handle(self, command: ProcessResponseCommand) -> None:
        form = self.form_repository.find_by_id(command.form_id)
        if not form:
            raise DomainException(f"Form {command.form_id} not found", code="FORM_NOT_FOUND")
        
        response = Response(
            response_id=command.response_id,
            form_id=command.form_id,
            answers=command.answers,
            started_at=command.started_at,
            submitted_at=command.submitted_at,
            ip_address=command.ip_address,
            user_agent=command.user_agent
        )
        
        form.validate_answers(command.answers)
        response.calculate_filling_time()
        
        country, city = self.geo_service.get_location(command.ip_address)
        response.enrich_geo(country, city)
        
        result = self.anti_spam_service.analyze(
            answers=command.answers,
            filling_time_sec=response.filling_time_sec,
            form_settings=form.anti_spam_settings
        )
        response.classify(result.quality_score, result.is_suspect, result.suspect_reason)
        
        self.response_repository.save(response)
        self.response_repository.update_aggregates(command.form_id, response)
        
        if response.is_suspect is False:
            rating_field = form.get_rating_field()
            if rating_field and command.answers.get(rating_field, 0) <= 2:
                self.notification_service.notify_critical_feedback(
                    form_id=command.form_id,
                    response_id=command.response_id,
                    rating=command.answers.get(rating_field, 0),
                    comment=command.answers.get("comment", "")
                )
```

### 3. Queries (Запросы)

***Созданные запросы:**

1. **GetAggregatesQuery** - запрос для получения агрегатов формы
   - Поля: form_id
   - Валидация: form_id не пустой
   - Файл: `application/query/get_aggregates_query.py`

2. **GetResponseByIdQuery** - запрос для получения ответа по ID
   - Поля: response_id
   - Валидация: response_id не пустой
   - Файл: `application/query/get_response_by_id_query.py`

3. **ListResponsesByFormQuery** - запрос для получения списка ответов формы
   - Поля: form_id, limit (1-1000), offset (>=0), include_suspect (опционально)
   - Валидация: form_id не пустой, limit в диапазоне 1-1000, offset не отрицательный
   - Файл: `application/query/list_responses_by_form_query.py`

**Read DTOs:**

1. **ResponseDto** - упрощённая модель ответа для чтения
   - Поля: response_id, form_id, answers, started_at, submitted_at, ip_address, user_agent, geo_country, geo_city, device_type, filling_time_sec, quality_score, is_suspect, suspect_reason
   - Метод: `from_domain(response)` - преобразует доменную сущность в DTO
   - Файл: `application/query/dto/response_dto.py`

2. **FormAggregatesDto** - упрощённая модель агрегатов для чтения
   - Поля: form_id, total_responses, quality_responses, suspect_responses, average_rating, quality_rate, suspect_rate
   - Метод: `from_domain(aggregates)` - преобразует доменный VO в DTO
   - Файл: `application/query/dto/form_aggregates_dto.py`

**Пример кода запроса:**

```python
@dataclass(frozen=True)
class ListResponsesByFormQuery:
    form_id: str
    limit: int = 100
    offset: int = 0
    include_suspect: Optional[bool] = None
    
    def __post_init__(self):
        if not self.form_id or not self.form_id.strip():
            raise ValueError("form_id cannot be empty")
        if self.limit < 1 or self.limit > 1000:
            raise ValueError("limit must be between 1 and 1000")
        if self.offset < 0:
            raise ValueError("offset cannot be negative")
```
**Пример кода DTO:**

### 4. Query Handlers

**Созданные обработчики запросов:**

1. **GetAggregatesHandler** - обработчик запроса GetAggregatesQuery
   - Репозиторий: ResponseRepository
   - Возвращает: FormAggregatesDto
   - Файл: `application/query/handler/get_aggregates_handler.py`

2. **GetResponseByIdHandler** - обработчик запроса GetResponseByIdQuery
   - Репозиторий: ResponseRepository
   - Возвращает: ResponseDto или None
   - Файл: `application/query/handler/get_response_by_id_handler.py`

3. **ListResponsesByFormHandler** - обработчик запроса ListResponsesByFormQuery
   - Репозиторий: ResponseRepository
   - Возвращает: List[ResponseDto]
   - Файл: `application/query/handler/list_responses_by_form_handler.py`

**Пример кода:**

```python
import logging
from application.query.get_response_by_id_query import GetResponseByIdQuery
from application.query.dto.response_dto import ResponseDto
from application.port.out.response_repository import ResponseRepository

logger = logging.getLogger(__name__)

class GetResponseByIdHandler:
    """Обработчик запроса GetResponseByIdQuery"""
    
    def __init__(self, response_repository: ResponseRepository):
        self.response_repository = response_repository
    
    def handle(self, query: GetResponseByIdQuery) -> ResponseDto:
        """Возвращает ответ по ID"""
        logger.info(f"Getting response {query.response_id}")
        
        response = self.response_repository.find_by_id(query.response_id)
        if not response:
            return None
        
        return ResponseDto.from_domain(response)
```

### 5. Application Service (Фасад)

**Реализованный сервис:** `ResponseApplicationService`

**Методы:**

| Метод | Тип | Возвращает |
|-------|-----|------------|
| `process_response(command)` | Command | void |
| `reclassify_response(command)` | Command | void |
| `get_aggregates(query)` | Query | FormAggregatesDto |
| `get_response_by_id(query)` | Query | ResponseDto |
| `list_responses_by_form(query)` | Query | List[ResponseDto] |

**Пример кода:**

```python
import logging
from application.command.process_response_command import ProcessResponseCommand
from application.command.reclassify_response_command import ReclassifyResponseCommand
from application.command.handler.process_response_handler import ProcessResponseHandler
from application.command.handler.reclassify_response_handler import ReclassifyResponseHandler
from application.query.get_aggregates_query import GetAggregatesQuery
from application.query.get_response_by_id_query import GetResponseByIdQuery
from application.query.list_responses_by_form_query import ListResponsesByFormQuery
from application.query.handler.get_aggregates_handler import GetAggregatesHandler
from application.query.handler.get_response_by_id_handler import GetResponseByIdHandler
from application.query.handler.list_responses_by_form_handler import ListResponsesByFormHandler
from application.query.dto.response_dto import ResponseDto
from application.query.dto.form_aggregates_dto import FormAggregatesDto

logger = logging.getLogger(__name__)

class ResponseApplicationService:
    """Фасад Application слоя. Делегирует вызовы хендлерам."""
    
    def __init__(
        self,
        process_response_handler: ProcessResponseHandler,
        reclassify_response_handler: ReclassifyResponseHandler,
        get_aggregates_handler: GetAggregatesHandler,
        get_response_by_id_handler: GetResponseByIdHandler,
        list_responses_by_form_handler: ListResponsesByFormHandler
    ):
        self.process_response_handler = process_response_handler
        self.reclassify_response_handler = reclassify_response_handler
        self.get_aggregates_handler = get_aggregates_handler
        self.get_response_by_id_handler = get_response_by_id_handler
        self.list_responses_by_form_handler = list_responses_by_form_handler
    
    # ========== Команды ==========
    
    def process_response(self, command: ProcessResponseCommand) -> None:
        """Обработать ответ"""
        self.process_response_handler.handle(command)
    
    def reclassify_response(self, command: ReclassifyResponseCommand) -> None:
        """Переклассифицировать ответ"""
        self.reclassify_response_handler.handle(command)
    
    # ========== Запросы ==========
    
    def get_aggregates(self, query: GetAggregatesQuery) -> FormAggregatesDto:
        """Получить агрегаты формы"""
        return self.get_aggregates_handler.handle(query)
    
    def get_response_by_id(self, query: GetResponseByIdQuery) -> ResponseDto:
        """Получить ответ по ID"""
        return self.get_response_by_id_handler.handle(query)
    
    def list_responses_by_form(self, query: ListResponsesByFormQuery) -> list:
        """Получить список ответов формы"""
        return self.list_responses_by_form_handler.handle(query)
```

## Контрольные вопросы

1. **В чём разница между Command и Query?**
   - Command изменяет состояние системы (CREATE, UPDATE, DELETE), возвращает void или ID. Query только читает данные без изменений, возвращает DTO или список DTO. В моей системе ProcessResponseCommand и ReclassifyResponseCommand — команды, GetAggregatesQuery, GetResponseByIdQuery, ListResponsesByFormQuery — запросы.

2. **Почему Command Handler возвращает только ID, а не весь объект?**
   - Чтобы избежать утечки доменной модели наружу. Клиент должен делать отдельный GET-запрос для получения полных данных. Это соответствует принципу CQRS и разделяет команды и запросы. Также это упрощает тестирование и снижает связанность.

3. **Где должна выполняться валидация: в команде, обработчике или доменной модели?**
   - Валидация примитивов (не пустые строки, диапазоны, форматы) — в команде (__post_init__). Бизнес-правила и инварианты — в доменной модели (classify, validate_answers). В обработчике только координация вызовов.

4. **Можно ли вызывать Query из Command Handler?**
   - Технически можно, но не рекомендуется, так как нарушает принцип CQRS. Query должны быть отделены от команд. В моей системе Command Handler не вызывает Query, только Repository для загрузки данных.

5. **Зачем разделять Request DTO (от клиента) и Command (внутренний)?**
   - Request DTO приходит извне (HTTP, очередь) и зависит от формата API. Command — внутренняя структура приложения. Разделение позволяет независимо менять API и бизнес-логику, добавлять валидацию на разных уровнях, преобразовывать форматы.
